# 页面角色矩阵（V6 标准）

## 角色定义

| 角色 | 代码 | 页数 | 标题规律 | 插入方式 |
|------|------|------|----------|----------|
| 概念页 | `concept` | 1 | 大纲原题 | keep / script |
| 图例页 | `diagram` | 1–4 | 同标题或副标题 | script / **com-clone** |
| 案例页 | `case` | 1–2 | 「案例：…」 | script / com-clone |
| 研讨页 | `workshop` | 0–1 | 「…研讨」「…练习」 | keep / manual |
| 过渡页 | `transition` | 1 | 第X章 / Chapter | **keep，禁止改** |
| 模板页 | `template` | 1 | `XXXX（插）` | keep，不展示 |
| 封面/封底 | `cover` | 各1 | 空或固定 | keep |

## 叙事链模式

一个知识点 = **概念 → 图例(1–3) → 案例(0–1)**，同标题多页是正常设计。

示例链：

```
信息化项目在组织中的定位 [concept P4]
  └─ 信息化项目在组织中的定位 [diagram P5]
信息化项目在组织中的价值 [concept P6]
  ├─ 信息化项目在组织中的价值 [diagram P7]
  └─ 信息化项目在组织中的价值 [diagram P8]
价值交付的全生命周期 [concept P9]
  └─ 价值交付的全生命周期 [diagram P10]
```

## 复合图 vs 单图

| 条件 | 方式 |
|------|------|
| shape_count < 15 且 pic_count ≤ 2 | Phase 4A 脚本 |
| shape_count ≥ 15 或含 GROUP/LINE | Phase 4B COM / 手工 |
| ITIL/PMBOK/组织架构类 | 默认 com-clone |

## PREP 话术按角色

### concept

- **P**：本页核心观点：{title}，是课程大纲明确要求掌握的关键知识点
- **R**：与立项、交付或 IT 服务管理岗位的日常决策直接相关
- **E**：结合图示逐条讲解，每点后追问「这与您当前工作如何关联」
- **P**：请牢固记住 {title}，是后续案例与练习的理解基础

### diagram

- **P**：本页以图例深化「{title}」，帮助学员建立可视化整体模型
- **R**：复杂框架若只讲文字，学员难以形成全局记忆；图例页降低认知负荷
- **E**：请按图从左到右/从上到下讲解；可让学员复述三个最关键节点
- **P**：合上 PPT 也应能画出或口述本页框架的核心结构

### case

- **P**：本页案例聚焦「{title}」，揭示典型失误与可复制的改进路径
- **R**：案例教学激活经验记忆，比纯理论更易形成风险预警
- **E**：追问「若您是项目经理，第一步会采取什么动作」
- **P**：带回岗位对照自查，制定一项可执行的预防或纠偏措施

### workshop

- **P**：本页为研讨/练习，目标是让学员产出与自身组织相关的结论
- **R**：被动听课难以转化；结构化研讨促成从「知道」到「用到」
- **E**：建议分组 8–10 分钟讨论，每组 1 分钟分享，讲师点评共性误区
- **P**：请记录本组结论，作为 30-60-90 天改进计划的输入

### transition

- **P**：本页承担章节过渡，标志进入新主题模块
- **R**：章节切换若缺乏铺垫，学员易产生知识混杂
- **E**：30 秒回顾上模块收获，30 秒预告本模块核心痛点
- **P**：引导学员在笔记本上标记章节分界，便于按模块复习

### insert（开发阶段，定稿去掉标题标记）

- 备注首行：`插入理由：{reason}`
- PREP 四段照常，强调与前后页的衔接
