# 项目章程生成技能

基于「AI赋能项目管理：特定行业/项目的项目章程的关键内容生成」（2601课程案例第154篇）的方法论，结合 TRACE 框架，支持为任意行业、任意项目生成规范的项目章程文档。

## 触发场景

当用户表达以下意图时应用本技能：
- 需要生成/编写项目章程
- 项目启动、项目授权、项目立项
- 提及「项目章程」「Project Charter」
- 需要基于模板填充项目章程内容

## 工作流程

### 第一步：互动式信息收集

在生成项目章程之前，**必须先以对话方式收集**以下必要信息。若用户未一次性提供，则逐项询问：

#### 必填信息

| 信息项 | 说明 | 示例 |
|--------|------|------|
| **项目标题/名称** | 项目的正式名称 | XX银行数据传输加密设备 |
| **行业** | 项目所属行业/领域 | 金融、政务、能源、医疗、制造业、教育等 |
| **项目经理** | 项目经理姓名及部门 | 何XX，产品经理 |
| **项目发起人** | 项目发起人姓名及职位 | 杨XX，区域销售经理 |

#### 建议收集的核心信息

| 信息项 | 说明 | 是否必填 |
|--------|------|----------|
| 项目目标（目的） | 项目要达成的核心目标，1～3 条 | 必填 |
| 项目成功标准 | 什么情况算项目成功 | 必填 |
| 详细范围 | 涵盖的阶段、资源、交付物 | 建议必填 |
| 客户名称及需求 | 客户单位、核心需求列表 | 建议必填 |
| 项目周期 | 起止时间或总周期 | 建议必填 |

#### 建议收集的扩展信息

| 信息项 | 说明 | 是否必填 |
|--------|------|----------|
| 项目概述 | 背景、规模、主要内容简述 | 建议必填 |
| 投资回报 | 待解决问题及解决后的回报 | 按需 |
| 项目假设条件 | 可能涉及的项目假设 | 建议必填 |
| 项目风险及防控措施 | 潜在风险及应对 | 建议必填 |
| 项目里程碑 | 里程碑及预计完成日期 | 建议必填 |
| 关键可交付成果 | 主要交付物列表 | 建议必填 |
| 项目审批要求 | 由谁对成功下结论、谁来签署结束 | 按需 |
| 项目退出标准 | 何种情况下可关闭或取消项目 | 按需 |
| 可行性分析 | 技术、资源成本等可行性 | 按需 |
| 项目团队组成 | 成员姓名、职务、联系方式 | 按需 |
| 项目投资金额 | 预算或投资额度 | 按需 |
| 软件工具/硬件设备 | 所需资源 | 按需 |

#### 一次性录入表单

若用户希望一次性提供全部信息，可引导其按以下格式填写（支持复制粘贴或逐条回答）：

```
【项目章程信息录入单】

一、基础信息
- 项目标题/名称：
- 行业：
- 项目经理（姓名及部门/职务）：
- 项目发起人（姓名及职位）：
- 起草人：
- 起草时间：
- 客户代表（如有，姓名及职务）：

二、项目核心
- 项目概述（背景、规模、主要内容，2～4 句）：
- 项目目标/目的（1～3 条）：
- 项目成功标准（什么情况算成功）：
- 详细范围（阶段、资源、交付物概述）：
- 项目周期（起止日期或总周期）：
- 可行性分析（技术、资源成本，简要）：

三、客户与需求
- 客户名称：
- 客户需求（可多条）：
- 投资回报（待解决问题及回报）：

四、假设与标准
- 项目假设条件：
- 项目审批要求（谁下结论、谁签署）：
- 项目退出标准（可关闭或取消的情形）：

五、风险与里程碑
- 项目风险及防控措施（风险1+应对；风险2+应对；……）：
- 项目里程碑（ milestone | 预计日期，可多行）：
- 关键可交付成果（可多行）：

六、资源与团队
- 项目投资金额：
- 项目团队组成（姓名、职务、联系方式）：
- 软件工具：
- 硬件设备：

七、其他
- 授权组织：
- 项目经理职责：
- 推广价值（如有）：
```

#### 一次性录入 UI

本技能目录下的 [input-form.html](input-form.html)，用户可在浏览器中打开、填写后点击「生成可复制文本」，将结果粘贴到 Cursor 对话中，实现一次性录入。

### 第二步：确定输出格式

1. **用户提供自定义 Word 格式**：若用户上传或指定了公司/客户的 Word 模板（.docx），则严格按照该模板的章节结构、样式、标题层级输出。
2. **默认格式**：若用户未提供自定义格式，则按照「项目章程交付样例」的结构和层级输出。完整结构见 [reference.md](reference.md)。

### 第三步：生成项目章程

1. 依据收集到的信息，按选定格式填充各章节内容。
2. 确保以下关键条目得到**专业、详细**的填写：
   - 项目假设条件
   - 项目风险及防控措施
   - 项目里程碑
   - 关键可交付成果
3. 行业术语、技术描述、日期格式等应与用户所述行业一致，避免泛泛而谈。
4. 若信息不足，对缺失条目标注「[待补充：XXX]」，并提示用户后续补充。

### 第四步：输出与修订

1. **输出格式**：优先生成 `.docx` 文件；若不支持直接生成 Word，则输出结构完整、表格清晰的 Markdown，便于用户复制到 Word。
2. **中文表述**：全文使用中文，避免错别字、乱码；数字、单位、日期格式符合中文习惯（如：20XX年X月XX日）。
3. 若用户需调整某部分，根据反馈单独修订并保持整体一致。

## 项目章程核心结构（默认）

默认采用「项目章程交付样例」的结构，包含以下部分：

1. 项目标题  
2. 起草人、起草时间  
3. 项目主要相关方联系人（表格式：职位、姓名及部门、职责、电话、电子邮件）  
4. 项目目标及评估信息  
   - 项目概述、项目目标（目的）、可行性分析、项目周期  
   - 投资回报、项目假设条件、客户名称、客户需求  
   - 项目成功标准、项目审批要求、项目退出标准  
   - 项目风险及防控措施、项目里程碑、关键可交付成果  
   - 推广价值（可选）、授权组织、项目经理职责  
5. 项目资源详细（投资金额、团队组成、软件工具、硬件设备）  
6. 项目签名（职位、签名栏、日期、承诺或意见）  

详细字段说明与示例见 [reference.md](reference.md)。

## 注意事项

1. **不臆造**：未收集到的联系人电话、具体金额、客户名称等，不得编造，应标注待补充或使用占位符（如 XX、XX@XX.com）。
2. **行业适配**：金融类强调合规、安全；政务类强调政策依据；企业类可侧重 ROI、交付周期；医疗/能源需体现行业监管要求。
3. **逻辑闭环**：项目目标 → 成功标准 → 里程碑 → 可交付成果，保持逻辑连贯。
4. **格式规范**：表格结构完整，便于在 Word 中进一步排版；参考 PMBOK 指南中的项目章程要素。
